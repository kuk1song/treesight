# Changelog

## Unreleased

- README demo: a 35-second video of a project's first run, in English and in Chinese: the command typed in a Claude Code session, the page while it draws and how long that takes ("about 4 minutes later"), the session's tree, a node and its quote, the project's open items, the report back in the conversation, and an end card with the install command; the view zooms in where the action is, so the text is readable at the README's width, and the captions stay within common reading speeds. The Chinese README says coding agent, and both READMEs drop the line on not being affiliated with Anthropic.
- Secrets are masked before any text is cut, so a private key in long pasted text or across a compaction summary's limit no longer leaves its first lines in the digest, the ledger or the page. Scrubbing also covers Groq, SendGrid, Telegram, Discord, Slack app and Shopify tokens, Google OAuth client secrets, Stripe webhook secrets, Slack and Discord webhook URLs, Azure storage account keys, `--password <value>` and the like, names ending in `_KEY` with a key-like value, passphrases, and all-digit passwords, and it takes linear time on long text without spaces, where the email, URL and token-name patterns could take seconds.
- Page: an open item whose due date is still ahead is listed under "With a due date", soonest first, with its date and the days left; before, it fell under "No time set" and its date showed only once it had passed.
- Sessions and items are found by words in any order (titles as written, so words that are masked on the page still match), and when several match, the message lists sessions' titles beside their ids, and items' labels instead of their ids. `set <item> blocked_by=<words>` finds the other item by its words. A number of 4 to 7 hex characters, such as 8080, only matches sessions of the current project.
- `/treesight:treesight <session> --restart` starts again after a run was stopped; until now a stopped run blocked the session for 20 minutes past its estimate. A run that was in fact still going cannot record the same entries twice.
- The digest is shown to the model in parts of at most 24,000 bytes rather than 20,000 characters: Claude Code saved a mostly Chinese part of 20,000 characters (about 35,000 bytes) to a file instead of showing it, so the model needed an extra step to read it.
- Page: before any session has a tree, the project page shows no open-items line; it used to say "Nothing left open" and "From 0 sessions with a tree". A session without a tree is drawn as a ring, and once some session has a tree, while others have none, a line under the open-items count says which mark is which, with counts. The page shows the project's name, with its path on hover; the button reads "N still open ›".
- Every session gets a one-sentence overview (会话概况), marked AI on the page: the session a run draws from the whole session, and the project's other sessions that need one (at most 30 a run) from a short excerpt each, which means short excerpts of other sessions now reach the model too. An overview from a session's own run is never replaced by one from an excerpt. Before, the page showed Claude Code's last recap, often in English and about where a session stopped, or a first prompt that was often pasted text.
- Page: a session without a tree says so on hover, and offers its overview only when it has one, or says it is being generated while a run writes it; when clicked, it shows its overview and two links, "Draw the tree" and "Open the session", which open Claude Code in a new terminal with the command typed in (its `claude-cli://` deep links; nothing runs until Enter); after a click, a command is offered to copy in case nothing opened (for "Open the session", `cd <folder> && claude -r <id>`). A run started from the page adds `--no-open`, so it updates the open page rather than opening another tab. A folder whose name had to be masked gets only the command to copy. Hovering a session with a tree shows its overview, also marked AI, and its numbers of nodes and open items. After a run started from the page, the white dot stays on the conversation you came from (the run's own conversation holds only the command and is not listed).
- Sessions run with `claude -p` or the Agent SDK are not listed unless drawn; the footer says how many.
- When a run is done, your conversation shows a line and a half under a 🌳 and the tool's name: what changed (only numbers that are not zero) and the page's link, plus a line only when something needs you, such as items to confirm; it is composed by the script, in the language of the session's prompts. A new plugin hook (`hooks/hooks.json`) asks the main conversation to pass it on as it is, instead of reading the page and writing a review of its own, as it did in every real test; the hook looks at each prompt in memory, keeps nothing, takes about 13 ms and lets every other prompt through. What the run was unsure about stays in the ledger and is no longer shown; a run read in two passes counts as one run under the session's title (before, the last pass's only), and those counts are left out when they only repeat the totals, as after a session's first run. The skill also says to fix its output only with Edit, never with sed, which would stop to ask you.
- One page per project, kept current: the browser opens it on the first run of a conversation (and again after three hours without an update there), and later runs and corrections in that conversation update the open page instead of opening another tab. The page checks a one-line stamp file next to it and reloads only when there is a newer build, instead of reloading every 20 seconds while a session is drawn; a page built on your machine adds `'strict-dynamic'` to its Content Security Policy so its own script can load that stamp.
- Page: while a session is being drawn, a pill at the top says "Drawing a tree" and "Session “…” · about N min · updates itself when done", beside a small tree that grows, rests and grows again; a pause button shows on hover, keyboard focus and where there is no hover, and the tree stays still with reduced motion and once the run seems to have stopped. The project tree now grows on such a page too, and a tab opened in the background grows when it is first shown.
- Page: every branch ends at its node's dot, which sits on the title's first line; the tip used to stop 7 to 20 px above the dot and 10 px away.
- Page: Chinese the model wrote is shown with full-width punctuation where it touches Chinese, as the interface has; quotes stay as written, and the extraction guide asks for it too. English: "Claude on 21 Sep at 10:07:", "Needs your “…” first", "Below, in the order raised", "No tree yet" in the legend.
- Page: an expanded node is one panel with its text flush left: its sentence (or, for a node that got stuck, the three rows of what happened), then its twigs as a list. A small "quote" mark after the sentence or a twig opens, under it, who wrote the quote, when, and its words, with Markdown's bold and code drawn as such; this replaces the "Show source" box. Open items in the drawer work the same way, and twigs show under a story too. Extraction may tie each quote to the twig it shows; the ledger stores quotes from the node's own message first.
- Extraction: twigs may have 16 units instead of 10, written as phrases that make sense on their own a month later; the 10-unit limit led to telegraphic twigs. Trees already drawn keep theirs.
- Page: ranked open items list the newer session's first, so two first-ranked items from different sessions no longer sit side by side; waiting items keep their rank.
- Extraction guide: one node for where a thread ended up; a node's message is where its outcome shows; Claude's own queued work is not something you wait on; an offer you did not take up is not an open item unless work waits on it; an undecided earlier item that decides whether a new one applies is set as its blocker; stuck time leaves out usage-limit waits and time away; "be conservative" removed.
- `dev/check_page.py` loads every view of the page in a headless browser and fails on any script error, and `dev/check_live.mjs` checks that an open page follows a correction and a run without a new tab, that with a mouse an open node shows its sentence and its quote, that a session's links offer the command after a click, that every branch ends at its dot, and that a page opened while a run is drawing grows, shows the small tree, pauses only by its button and says which overviews are being generated; the tests run both when a browser is found.
- The ledger can now hold a `twig` on a node's quote and twigs of up to 16 units, which 0.1.3 and earlier refuse when they draw the page, and summaries, which they ignore: after updating, do not go back to an earlier version.
- Wrong arguments to the command line answer `{"ok": false, …}` like other errors. Hover cards and expanded nodes wrap long file names too.
- Documents: a run with nothing new takes a few short model requests (about 20 s), not one; CONTRIBUTING counts the tests that need node and lists every step of the release workflow. Both README videos are re-recorded: an open node shows its twigs and opens a quote from its mark.

## 0.1.0 (2026-10-20)

First public release.

- `/treesight:treesight` draws a Claude Code session as a tree of what got done and what was found, with setbacks shown as scars that open into a three-row story, and lists what is still open across the project: yours to do or waiting, who it waits on and for how long, overdue, blocked by another item.
- Extraction runs in a forked subagent with the user's own Claude Code. It reads the session's texts whole, in passes of up to 150,000 characters for long sessions, and the skill pre-approves only running treesight's own script and writing under `~/.cache/treesight`. The skill sets xhigh effort, so results do not depend on the session's effort level. Every node and open item carries a quote that a script checks against the session before saving.
- Append-only ledger in `~/.local/share/treesight/`: later runs read only new messages, treesight's own command and the turn spent on its report are not counted, closes need a quote from no earlier than the item, unsure ones wait for the user, an older session drawn after newer ones is checked against what they recorded, and the user's own corrections (`close`, `reopen`, `hide`, `set`) are checked and always win. The ledger keeps each session's title and times, so a session stays on the page after Claude Code deletes its transcript. Writes are locked, pages are written under the same lock so an older state never replaces a newer page, and files are readable only by the user.
- Static page with no network requests, a Content Security Policy, English and Chinese interface, project and session views with browser history. It opens on the session being drawn, lists every run in progress, and says when they seem to have stopped. On macOS it is opened with `open -a` and the default browser; `$BROWSER` is honoured.
- Transcript reading, secret scrubbing and IPv4 and email masking in one adapter; data formats as JSON Schema; tests with the Python standard library only.
